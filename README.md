# Toi Line

Живой праздничный LED-экран для казахского тоя. Гости по QR присылают селфи с пожеланием, открытка выходит на
большой экран. «Конверт» (VIP) с переводом на Kaspi организатора выходит вне очереди, в золоте. Модератор
(тамада) одобряет открытки и подтверждает переводы. После тоя: альбом поздравлений и отчёт организатору.

Продуктовый бриф: [`docs/BRIEF.md`](docs/BRIEF.md).

## Ссылки

| Адрес | Кто открывает |
|---|---|
| `/` | Админка: создать той, список мероприятий (вход по `ADMIN_KEY`) |
| `/g/<id>` | Гость (QR на столах), `?t=7` подставляет номер стола |
| `/m/<id>/<ключ>` | Пульт тамады: Эфир, Экран (оформление), Отчёт, Ссылки и QR. Организатору не отправлять |
| `/s/<id>/<ключ>` | LED-экран: оператор открывает в Chrome, кликает или жмёт F11 |
| `/a/<id>` | Альбом показанных открыток |
| `/o` | Кабинет организатора (ТЗ 0.8): вход по логину (номер мероприятия) и паролю из админки. О празднике, Приглашение 4:5 и именные (ZIP), Поздравления и итог, Фото пары. Модерации нет |
| `/g/demo`, `/s/demo/demo` | Постоянный демо-той: всё сразу на экране, конверт без перевода |

Старые ссылки вида `/toionline/...` перенаправляются на новые.

## Устройство

- Python 3.10+, **только стандартная библиотека**. `server.py` — HTTP, `toi.py` — вся логика (база, API, реальное время).
- Фронт: `static/` — чистый HTML/CSS/JS без сборки. `common.js` (шаблоны, фоновые узоры, орнамент, тема), `scene.js` + `led.css` (сцена экрана).
- Реальное время: Server-Sent Events. Сервер должен работать одним процессом (подписчики в памяти).
- Офлайн экрана: открытки в `localStorage`, страница и фото в кэше сервис-воркера (`static/sw.js`).
- Данные: `DATA_DIR/toi.db` (SQLite) и фото `DATA_DIR/toi/<id>/`. Деньги через сервис не идут.
- Лимит: бесплатное поздравление — одно с устройства в 30 минут (cookie `toi_dev`), конверты без ограничений.
- Подробно (API, база, статусы, правила показа): [`docs/HANDOFF.md`](docs/HANDOFF.md).

## Запуск и проверка

```bash
ADMIN_KEY=test PORT=8123 DATA_DIR=./data python server.py
BASE=http://127.0.0.1:8123 ADMIN_KEY=test python test_toi.py
```
Открыть http://127.0.0.1:8123/s/demo/demo и в другом окне (или с телефона в той же сети) http://127.0.0.1:8123/g/demo.

## Railway

1. railway.com → **New Project → Deploy from GitHub repo → toiline**. Dockerfile найдётся сам.
2. **Variables:** `ADMIN_KEY` — длинный пароль для админки. `DATA_DIR` = `/data`.
3. **Volumes:** том с путём монтирования `/data` (без него фото и тои пропадут при перезапуске).
4. **Settings → Networking → Generate Domain** или свой домен (например `toi.postik.link`: CNAME на адрес Railway).
5. Одна реплика (по умолчанию так и есть).

## Правила работы

- Каждая правка в отдельной ветке и через pull request. `main` сразу выкатывается на рабочий сайт.
- Перед работой `git pull`. CI гоняет `test_toi.py` на каждый PR.
- Новые внешние зависимости не добавлять без необходимости.
