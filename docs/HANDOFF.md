# Toi Line — передача проекта (состояние на 16.11.2026)

Этот файл можно целиком вставить в другой ИИ (DeepSeek и т.п.), чтобы продолжить работу с того же места.
Продуктовый бриф с решениями по деньгам, партнёрам и шаблонам: `docs/BRIEF.md`.
План работ на следующий этап (ТЗ по задачам): `docs/TZ.md`.

## 1. Что это

Интерактивный праздничный LED-экран для казахского тоя. Вместо JPG-заставки оператор открывает в Chrome страницу
экрана. Гости сканируют QR, делают селфи и пишут пожелание, открытка выходит на большой экран. «Конверт» (VIP) —
поздравление с переводом денег на Kaspi организатора: выходит вне очереди, в золоте, сумма видна всем.
Модератор (тамада) одобряет открытки и подтверждает переводы. После тоя — альбом поздравлений и отчёт организатору.

## 2. Где что лежит

## 3. Стек и ограничения

- Python 3.13, **только стандартная библиотека**: `http.server.ThreadingHTTPServer`, `sqlite3`.
  Внешние пакеты не добавлять без необходимости.
- Фронт: чистый HTML/CSS/JS без сборки, шрифты Google Fonts (Great Vibes, Cormorant Garamond, Playfair Display, Forum, Lobster, Comfortaa, Manrope).
- Реальное время: **Server-Sent Events** (веб-сокетов в stdlib нет). Пинг каждые 15 сек (Cloudflare рвёт тишину через 100 сек),
  поток сам закрывается через ~270 сек, браузер переподключается и пересинхронизируется через `/state`.
- Подписчики SSE хранятся в памяти процесса, поэтому сервер должен работать **одним процессом/репликой**.
- Данные: `DATA_DIR/toi.db` и фото `DATA_DIR/toi/<id мероприятия>/<случайное имя>.jpg`. На Railway `DATA_DIR=/data` (том).
- Деньги через сервис **не идут**: гость переводит на Kaspi организатора, модератор сверяет вручную.

## 4. Ссылки и роли

На каждое мероприятие:
- Гость: `/g/<id>` (можно `?t=7` — подставит номер стола)
- Пульт модератора/организатора: `/m/<id>/<mod_key>`
- LED-экран: `/s/<id>/<led_key>` (оператор: открыть в Chrome, кликнуть или F11)
- Альбом: `/a/<id>`
- Админка: `/` (вход по переменной `ADMIN_KEY` (или `TOI_ADMIN_KEY`); 10 неверных ключей за 15 мин закрывают адрес)

id — 6 символов из `abcdefghjkmnpqrstuvwxyz23456789`, ключи — 10 таких символов.

**Постоянный демо-той** (создаётся сам при старте, без модерации, конверты без перевода):
- Гость: <домен>/g/demo
- Экран: <домен>/s/demo/demo
- Пульт демо: ссылка видна в админке `/`.

## 5. Правила показа (LED)

- Обычная открытка — 8 сек. Конверт — 15 сек + 2 сек за каждую 1 000 ₸, максимум 60 сек (`durOf` в common.js).
- Карточка на экране — полароид: фото в белой рамке с полем для подписи (имя и стол) снизу, пожелание рядом. У конверта бумага золотая. Верстка в `led.css` (`.polaroid`), сцена в `scene.js`.
- Порядок: сначала конверты (крупная сумма раньше), потом обычные по времени одобрения.
- От 10 000 ₸ — салют. Бегущая строка: «★ Имя подарил(а) конверт N ₸» по последнему показанному конверту.
- Нет новых открыток — заставка праздника (имена, орнамент, золотой блик, пыль). QR на экране нет: гости сканируют QR на столах.
- Экран сам отмечает показ (`POST …/shown`), если сети нет — копит в очереди и отправляет позже.
- Офлайн: открытки и настройки в `localStorage` (`toi-led-<id>`), страница/скрипты/фото в Cache Storage (`toi-v1`).

## 5a. Лимит бесплатных поздравлений

- Бесплатное поздравление — **одно с устройства в 30 минут** (`FREE_EVERY` в `toi.py`). Считаем по cookie
  `toi_dev` (таблица `free_pass`: устройство + мероприятие), а не по IP: в зале все гости на одном Wi-Fi.
- Cookie нет — считаем по адресу, поэтому бот, который её выкидывает, всё равно упирается в лимит.
- **Конверты (платные) без ограничений** — их можно отправлять сколько угодно и сразу после бесплатного.
- Ответ 429: `{"error": "...", "retry": секунд}` — страница гостя показывает обратный отсчёт и не открывает форму.
- Ручного «разрешить ещё» нет: правило одно для всех.
- Отдельно против ботов: `GUEST_LIMIT` — 60 открыток с адреса за 10 минут.

## 6. Статусы открытки

`pending` (ждёт модератора) → `approved` (в очереди на экран) → `shown` (показана, в альбоме). `hidden` — скрыта.
- Конверт всегда `pending`, пока модератор не нажмёт «Деньги пришли · в эфир» (`approve` ставит `paid=1`).
- Обычная открытка сразу `approved`, если в настройках выключено «проверять перед показом» (`moderation=false`).
- В демо-тое (`cfg.demo=true`) всё сразу `approved`, конверты `paid=1`.
- «Показать ещё раз» (`requeue`): `shown` → `approved`.

## 7. База (SQLite, `toi.db`)

```sql
events(id TEXT PK, mod_key TEXT, led_key TEXT, created INTEGER ms, cfg TEXT JSON, deleted INTEGER)
cards(id INTEGER PK, eid TEXT, created INTEGER ms, name, msg, frame ('orn'|'soft'|'classic'), tbl,
      amount INTEGER ₸ (0 = обычная), photo (имя файла без .jpg или ''), status, paid, approved_at, shown_at,
      gtoken (секрет гостя для проверки статуса), ip)
```

`cfg` (проверяется в `clean_cfg`): `type` (wedding|jubilee|uzatu|tusau), `kind`, `names`, `sub`, `date`, `hello`, `quick` (список пожеланий),
`tpl` (pink|gold|bluemed|turq|green|royal|circle|sky), `card` (auto|portrait|landscape — формат карточки), `bgpat` (none|spiral|medallion|ring|heart|lattice|stripe|damask|mandala —
фоновый узор, рисуется кодом в `renderPattern`), `bg1`,`bg2`,`c1`,`acc` (#hex), `font`, `size` (напр. `9cqw`), `sheen` (12s|30s|60s),
`splash` (имя файла), `moderation`, `kaspi_name`, `kaspi_phone`, `kaspi_link` (только https), `pct` (комиссия %), `deposit` (₸), `demo`.

## 8. API

Все пути с префиксом `/api`. Ответы JSON, ошибки `{"error": "текст"}`.

| Метод и путь | Кто | Что |
|---|---|---|
| `GET /admin/events` (заголовок `X-Toi-Admin`) | админ | список мероприятий со ссылками и суммой конвертов |
| `POST /admin/events` | админ | создать (тело — поля cfg) → `{id, links}` |
| `POST /admin/events/<id>/delete` | админ | удалить (мягко) |
| `GET /e/<id>` | гость | публичные настройки праздника |
| `POST /e/<id>/card` `{name,msg,frame,table,amount,photo:dataURL JPEG}` | гость | отправить открытку → `{id,token,status,pos}`; лимит 12 открыток с адреса за 10 мин; фото ≤ 3 МБ |
| `GET /e/<id>/card/<cid>?token=` | гость | статус своей открытки и место в очереди |
| `GET /a/<id>` | все | альбом (только `shown`) |
| `GET /m/<id>/<key>/state` | пульт | настройки, все открытки, ссылки, сколько экранов на связи |
| `GET /m/<id>/<key>/stream` | пульт | SSE: `hello`, `card`, `config` |
| `POST /m/<id>/<key>/act` `{id, action: approve|hide|requeue}` | пульт | действие с открыткой |
| `POST /m/<id>/<key>/cfg` | пульт | изменить настройки (частично); `splash`: dataURL JPEG или `''` |
| `GET /s/<id>/<key>/state` | экран | настройки + открытки `approved`/`shown` |
| `GET /s/<id>/<key>/stream` | экран | SSE: `hello`, `card`, `config` |
| `POST /s/<id>/<key>/shown` `{ids:[…]}` | экран | отметить показанные |

Фото: `GET /p/<id>/<24 hex>.jpg`. Статика: `/static/<file>`, сервис-воркер: `/sw.js`.

## 9. Как запустить и проверить

```bash
ADMIN_KEY=test PORT=8123 DATA_DIR=./data python server.py
BASE=http://127.0.0.1:8123 ADMIN_KEY=test python test_toi.py
```
Открыть http://127.0.0.1:8123/g/demo и http://127.0.0.1:8123/s/demo/demo. CI (GitHub Actions) гоняет pyflakes и `test_toi.py` на каждый PR.
Изменения в `main` сразу уходят на рабочий сайт: работать через ветки и PR.
